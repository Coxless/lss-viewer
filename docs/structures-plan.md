# 有名な大規模構造の強調表示：実装計画

有名な構造を一覧にして、チェックを付けると地図上で色が付き、飛んで見に行けるようにする計画です。
concept 5.8 の「任意のマーカー」（v1.1）を発展させたものです。調査日：2026-11-01

> 依頼にあった「cosmo heritage」は検索で特定できませんでした。「世界遺産のように、名前の付いた構造を一覧にして巡れるもの」と解釈しています。

---

## 1. 今のデータで何が見えるか

SDSS DR18（z 0.01〜0.12、45万銀河）に対して、`lss-viewer-cli import-structures` で実測した値です。領域は `structures/catalog.json` にあり、各項目に根拠（`basis`）と出典（`refs`）があります。

- **範囲内の割合：** 領域のうち、観測された方向と距離に入る割合
- **平均との比：** 領域内の銀河数を、同じ距離の平均密度から期待される数で割った値。1 より大きいと高密度、小さいと低密度

| 構造 | 種類 | 距離 (Mpc/h) | 範囲内の割合 | 平均との比 | 銀河数 |
|---|---|---|---|---|---|
| Coma 銀河団 | 銀河団 | 69 | 99% | 7.29 | 1,013 |
| Coma 超銀河団 | 超銀河団 | 69 | 100% | 3.45 | 3,032 |
| Hercules 超銀河団 | 超銀河団 | 107 | 92% | 2.18 | 4,841 |
| Corona Borealis 超銀河団 | 超銀河団 | 206 | 100% | 1.82 | 3,618 |
| Leo 超銀河団 | 超銀河団 | 110 | 100% | 1.29 | 2,963 |
| Sloan Great Wall | 壁 | 222 | 87% | 1.27 | 21,504 |
| CfA2 Great Wall | 壁 | 69 | 99% | 1.22 | 20,251 |
| Boötes ボイド | ボイド | 148 | 100% | 0.41 | 1,274 |

**このデータでは見えないもの：**

| 構造 | 理由 |
|---|---|
| おとめ座銀河団 | 近すぎる（r≈11、データは z≥0.01、r≥30） |
| Shapley 超銀河団 | 範囲外（赤緯 −31°、観測方向 0%） |
| Laniakea（Norma 方向） | 範囲外（観測方向 0%） |
| Perseus-Pisces 超銀河団 | ほぼ範囲外（観測方向 3%） |
| BOSS Great Wall | 遠すぎる（z≈0.47） |
| Hercules–Corona Borealis Great Wall | 遠すぎる（z≈2） |

**決定：** 見えないものも一覧に残し、グレーで理由を添えます。「なぜ見えないか」も、宇宙の地図を理解する手がかりになるからです。

## 2. 体験

```
有名な構造                     [全部オフ]
☑ ■ Sloan Great Wall   壁      6.5億光年先   ▶
☑ ■ Coma 銀河団        銀河団  3.2億光年先   ▶
☐ ■ Boötes ボイド      ボイド  7.1億光年先   ▶
────────────
このデータでは見えないもの
   おとめ座銀河団   近すぎます
   Shapley 超銀河団 観測範囲の外です
周囲の明るさ ━━●━━━
```

| # | 要件 |
|---|---|
| H1 | チェックを付けると、その構造の銀河に色が付き、地図上に名前が出る |
| H2 | 1 つでもチェックがあると周囲の銀河が暗くなり、構造が浮かび上がる。暗さはスライダーで変えられる |
| H3 | ▶ で構造へ飛ぶ。壁は扇形図（薄い板）、銀河団と超銀河団はその周りを回れる距離で見る。飛んだ構造には自動でチェックが入る |
| H4 | 行を開くと、説明、大きさ、発見の経緯、論文へのリンクが出る |
| H5 | ボイドは銀河がないので、色を付けられない。境界を球の線で描き、中を暗くしない |
| H6 | チェックの状態を URL に入れて共有できる（`#v=...&s=sgw,coma`） |
| H7 | スマホでは ▶ を押すとシートが閉じる |

## 3. 設計

### 構造のデータ

`data/` は生データ用で git に入れないので、`structures/catalog.json` を新設して git で管理します。

```json
{
  "id": "sgw",
  "name": "Sloan Great Wall",
  "type": "wall",
  "region": { "shape": "sky-box", "ra": [149, 220], "dec": [-4, 8], "z": [0.07, 0.085] },
  "minDelta": 0.0,
  "color": "#ffb454",
  "view": "fan",
  "summary": "...",
  "size": "約14億光年",
  "refs": [{ "label": "Gott et al. 2005", "url": "https://arxiv.org/abs/astro-ph/0310571" }]
}
```

- 領域の形は 2 種類です。壁は `sky-box`（赤経、赤緯、z の範囲）、それ以外は `sphere`（中心と半径）です
- 解説文は論文の転載をせず、自分で書きます

### データ形式と CLI

`lss-viewer-cli import-structures --dataset DIR --catalog structures/catalog.json`

- `layers` に `kind: "regions"` を追加し、`structures.json` を出力します。concept 5.8 のレイヤーの枠組みに乗ります
- 構造ごとに範囲内の割合、銀河数、平均との比を計算し、`status`（`visible`、`outside`）と理由を付けます。1 章の表は、このコマンドで再現します
- `docs/format.md` と concept 5.8 を更新します

### 色付けの方法：シェーダーで判定する

| 案 | 長所 | 短所 |
|---|---|---|
| **A. シェーダーで領域を判定（採用）** | データ形式の点を変えない。GPU メモリが増えない。切り替えが即時 | 頂点ごとの計算が増える |
| B. タイルの読み込み時に所属を計算し、属性を追加 | 描画が軽い | 点の属性に空きが 1 bit しかなく、別バッファが必要で GPU メモリが増える |
| C. 構造ごとの所属リストを事前に作る | 厳密 | データが増え、Range 取得の設計が複雑になる |

同時に強調できる構造は 8 個までとし、超えたらチェックを付けられないことを表示します。

### 形を出す：密度で絞る

領域に入る点を全部塗ると、箱の形が見えるだけで、壁の形は見えません。そこで、`density.bin.gz` を 3D テクスチャにして、**領域の中で δ が `minDelta` 以上の銀河だけ**に色を付けます。

- 密度格子はしきい値の変更と同じく、最初にチェックを付けたときに取得します。初回の転送量は増えません
- 一度取得すれば、しきい値スライダーと共有します
- 格子は 1 セル約 6 Mpc/h で平滑化も約 8 Mpc/h なので、銀河団の内部は分かれません。壁や超銀河団の形を出すには十分な見込みです（S3 で確認）

### 色の設計

- 点は加算合成なので、**密集すると色が白に飛びます**。強調する点は明るさを抑えて彩度を保ちます。ここが最大の見た目のリスクなので、S2 の最初に試します
- 色はシアン（独自計算）とマゼンタ（VAST）を避け、色覚の違いでも区別しやすいものから選びます

## 4. 作業の順序

| 段階 | 内容 | 完了の条件 | 規模 |
|---|---|---|---|
| S0 | 論文と照合して `catalog.json` を作る（位置、範囲、大きさ、解説、出典） | 全候補に出典がある。領域が論文の値と一致する | S |
| S1 | `import-structures`、データ形式、状態の計算 | 1 章の表が再現される。範囲外の 6 件が `outside` になる | S |
| S2 | シェーダーの強調、周囲の減光、一覧、地図上の名前 | H1、H2、H5。実データで色が白飛びしない（目視） | M |
| S3 | 密度テクスチャによる絞り込み | Sloan Great Wall が箱ではなく弧に見える（目視） | M |
| S4 | 飛行、解説の展開、URL 共有、スマホ | H3、H4、H6、H7 | M |

S2 までで「チェックで色が付く」は動きます。S3 が見た目を決める段階です。

## 5. テスト

- **Rust：** カタログの読み込み、状態の計算、範囲外の判定、`sky-box` の赤経 0° またぎ
- **ユニット：** シェーダーと同じ判定式を TypeScript でも書いて、既知の点で比べる。URL の往復
- **E2E：** チェックで描画が変わる、8 個の上限、グレー行は選べない、URL から復元できる、スマホでシートが閉じる
- **基準画像：** 固定の模擬データに、位置の分かっている領域を置いて比較する
- **性能：** 8 個すべてオンで `?bench=1` を実行する。PC 60 fps、中位スマホ 30 fps を維持する

## 6. リスク

| リスク | 対策 |
|---|---|
| 構造の境界は文献でも定義が曖昧で、領域の取り方で見た目が変わる | 画面に「範囲は目安」と書き、出典の値を使う。厳密な所属は目指さない |
| 比が小さい構造（Leo 1.35）は強調しても目立たない | S3 で確かめ、形が出なければ一覧から外すか、銀河団を中心にした表示にする |
| 加算合成で色が白飛びする | S2 の最初に検証する。だめなら強調点だけ別の合成にする |
| 頂点シェーダーの負荷と、スマホでの動作 | スマホ実機の計測が未実施。S2 の前に、現状の基準値を測っておくと比較できる |
| パネルが長くなる | 改善案 E（折りたたみ）を先に、または同時に入れる |

## 7. この計画に含めないもの

- 利用者の CSV での強調（カタログの判定は CLI だけで行う）
- BOSS や DESI のデータ追加（遠くのグレートウォールを見るには別の作業が必要）
- 構造の自動検出。一覧は人が選んだカタログです

## 8. 実装の結果

S0〜S4 を実装しました。

**計画から変えた点：**

| 変更 | 理由 |
|---|---|
| Sloan Great Wall の赤経を 149〜220° から 130.5〜210° に変更 | Gott らの 8.7h〜14h に合わせた。元の値は Einasto らの標本の範囲で、壁そのものの範囲ではなかった |
| 強調する点を 2 パス目で「上に重ねる」合成で描く | 加算合成では白飛びは避けられないので、リスク欄の対策を最初から採用した。領域に触れないタイルは判定と 2 パス目を省く |
| ボイドだけのチェックでは周囲を暗くせず、スライダーも隠す（H2 の例外） | ボイドは周りの銀河があって初めて見える |
| ボイドの飛行は扇形図（厚さ 20 Mpc/h） | 3D のままでは手前と奥の銀河で穴が見えなかった |
| 強調中は自動モードでも点を間引かない | 構造は銀河でできているので、縮小時に間引くと形が消える |
| 折りたたみは見出しのクリックだけの最小の形。初期状態で閉じるのは「軽さのしくみ」だけ | パネルの長さへの対策。リスク欄の案 E |

**確認できなかった点：**

- Leo 超銀河団の中心は目安。確認できた構成銀河団の位置は Abell 1185 だけです
- CfA2 Great Wall の赤緯の南限（8.5°）は出典で確認していません
- Sloan Great Wall の z の範囲（0.065〜0.095）は、中央値と主要な超銀河団の距離から選んだもので、文献に書かれた範囲ではありません
- 論文の一部は全文を読めず、要約の値が混じります。Wikipedia を出典にした項目もあります。画面に「範囲は目安」と書き、項目ごとに根拠を載せています

**性能（GTX 1660 Ti、1920×994、ヘッドレス Firefox、実データ、上限 100 万点、15 秒のカメラ経路）：**

| 条件 | 平均 fps | 低位 5% | 平均点数 | GPU メモリ |
|---|---|---|---|---|
| 強調なし | 128 | 91 | 32 万 | 3.8 MB |
| 8 個すべて強調 | 128 | 108 | 37 万 | 4.9 MB |

スマホの実機では未計測です。Playwright の E2E は 8 件追加し、基準画像は `web/e2e/snapshots/structures.png` です。
